# Контекст

Задача IPRSV1-19, дословно: «nginx работает некорректно совместно с
программой, установленной на этом сервере. Нужно: остановить службу nginx и
отключить её автозапуск. Не удалять nginx полностью — только выключить, чтобы
можно было включить обратно при необходимости.» На уточняющий вопрос, какая из
двух машин проекта имеется в виду, Максим ответил 07.09.2026 в чате задачи:
«давай руби на обе». Поэтому работа идёт на **обеих** машинах:

- сервер 1 — `201.34.132.26` (`VDSWIN2K22`, домен `scanvision.online`);
- сервер 2 — `200.165.238.242` (домен `scan-vision.ru`).

**Какая именно программа конфликтует с nginx и в чём конфликт — в задаче не
названо, и на машинах этому нет ни одного следа.** Замеры 07.09.2026 с раннера
по SSH (только чтение):

- сервер 1: два процесса `nginx.exe` (PID 2968 — мастер, 4592 — воркер),
  StartTime 31.08.2026 20:16:57; мастер слушает `443`, `16604`, `16605`; порт
  `80` держит другой процесс (PID 5692, tomcat CMSV6). Последние записи
  `C:\nginx\logs\error.log` — от 31.08.2026 (SSL-хендшейки чужих сканеров,
  OCSP-резолв, `client intended to send too large body`), ничего про порты и
  конфликты. Установленное ПО с 25.08.2026: только Google Chrome (04.09) и
  Microsoft Edge (06.09);
- сервер 2: два процесса `nginx.exe` (PID 3532, 9956), StartTime 03.09.2026
  15:57:44; слушает `443`, `16604`, `16605`; порт `80` — другой процесс
  (PID 2692, tomcat). Последние записи `error.log` — от 03.09.2026, штатные для
  установки (`nginx.pid` не найден, `OpenEvent ... Access is denied`).
  Установленное ПО с 25.08.2026: Zabbix Agent (29.08), QEMU guest agent
  (29.08), `CMSServerV6_WIN_7.36.1_20251023` (03.09),
  `MDVRPlayer_WIN_7.36.1_20251022` (03.09), MSVC-рантаймы (03.09), Microsoft
  Edge (06.09).

Причину конфликта в этой задаче не диагностируем и не выдумываем: просьба
Максима конкретна и обратима, а гипотеза без подтверждения хуже, чем её
отсутствие. Единственное, что делается по этой части, — шаг 4 ниже фиксирует,
занял ли кто-нибудь освободившиеся порты.

🔴 **Главное расхождение с формулировкой задачи: службы nginx на этих машинах
нет.** `Get-Service` c фильтром по имени и DisplayName не возвращает ничего —
проверено 07.09.2026 на обеих машинах. nginx запускается **задачей планировщика
`nginx_run`** (проверено 07.09.2026):

- сервер 1: действие `C:\nginx\run_nginx.bat`, триггер `MSFT_TaskBootTrigger`
  (при старте системы), `UserId SYSTEM`, `RunLevel Limited`, состояние `Ready`,
  последний запуск 31.08.2026 20:16:16 с результатом `0`;
- сервер 2: то же действие `C:\nginx\run_nginx.bat`, тот же boot-триггер,
  `UserId SYSTEM`, `RunLevel Highest`, рабочая папка `C:\nginx`, состояние
  `Ready`, последний запуск 03.09.2026 15:57:57 с результатом `0`.

Поэтому «остановить службу и отключить автозапуск» реализуется как
`Disable-ScheduledTask` + снятие живого процесса, а не `Stop-Service`/`sc
config` — последние на этих машинах просто не найдут объект.

**Последствие, принимаемое сознательно.** После отключения на обеих машинах
перестаёт работать весь HTTPS: `https://scanvision.online/` и
`https://scan-vision.ru/` (порт 443) и оба TLS-листенера медиа `16605`
(`GPSLoginSvr`) и `16604` (`GPSMediaSvr`), заведённые задачей IPRSV1-17.
Остаётся вход по `http://` на порт 80 — его держит tomcat CMSV6 напрямую, и
это штатная точка входа: в `nginx.conf` нет ни `listen 80`, ни HSTS, ни
редиректа 80→443, так что отключение nginx порт 80 не затрагивает. Сертификаты
(купленный GlobalSign на сервере 1, Let's Encrypt на сервере 2) остаются на
диске нетронутыми — их просто некому отдавать, пока nginx выключен.

# Что сделать

🔴 **Работа идёт на двух разных машинах, адрес каждой задаётся явной
константой в каждой команде.** Переменные `SERVER`/`LOGIN`/`PASSWORD` в сессии
раннера и переменная репозитория `SERVER` указывают только на сервер 1
(`201.34.132.26`) — на них полагаться нельзя, иначе половина работы уйдёт не на
ту машину. Доступ ключом `ai-runner@ai-runners`: сервер 1 — через готовый алиас
`ssh iprsv1`, сервер 2 — `ssh -i ~/.ssh/id_ed25519
Administrator@200.165.238.242`. Пароли в команды не подставлять и в репозиторий
не писать.

Многострочный PowerShell подавать только через `-EncodedCommand` (UTF-16LE →
base64): подача на stdin молча обрывается на первом многострочном
`foreach`/`if`/`try` с кодом возврата 0. Первой строкой любого скрипта,
читающего `Get-ScheduledTask`/`Get-NetTCPConnection`/`Get-NetFirewallRule`,
ставить `$ProgressPreference = 'SilentlyContinue'`.

**1. Замер «до», отдельно по каждой машине.** `Get-Process nginx` (PID и
`StartTime`), `Get-NetTCPConnection -State Listen` с портами `80`, `443`,
`16604`, `16605` (кто чем владеет), `Get-ScheduledTask -TaskName nginx_run`
(`State`), и снаружи с раннера: `https://scanvision.online/` и
`https://scan-vision.ru/` → ожидание `200` с валидной цепочкой,
`http://scanvision.online/`, `http://201.34.132.26/`,
`http://200.165.238.242/` → ожидание `200`. Цифры и PID нужны в документации
как пара «до/после».

**2. Отключить автозапуск на каждой машине:**

```powershell
Disable-ScheduledTask -TaskName nginx_run
```

Задачу **не удалять** и `C:\nginx\run_nginx.bat` не трогать — вся обратимость
держится на том, что задача осталась на месте в состоянии `Disabled`.
Результат проверять фактом: `Get-ScheduledTask -TaskName nginx_run` →
`State Disabled`.

**3. Снять живой процесс на каждой машине:**

```cmd
taskkill /F /IM nginx.exe
```

Именно `taskkill`, а не `nginx.exe -s stop`/`-s reload`: мастер запущен от
`SYSTEM`, а SSH-сессия идёт от `Administrator`, поэтому сигнальные команды
падают с `OpenEvent(...) failed (5: Access is denied)` — это известная ловушка
обеих машин, а не ошибка исполнителя. После этого проверить **обе** вещи:
`Get-Process nginx` не возвращает ничего (ловушка «залипшего мастера»:
отвязанный от job-объекта процесс переживает остановку задачи и продолжает
слушать), и `Get-NetTCPConnection -State Listen` больше не показывает `443`,
`16604`, `16605`. Порт `80` при этом обязан остаться за прежним процессом
tomcat.

**4. Проверка «после» и фиксация того, что заняло порты.** Снаружи с раннера:
`https://scanvision.online/` и `https://scan-vision.ru/` больше не отвечают
(ожидается отказ в соединении или таймаут), `http://scanvision.online/`,
`http://201.34.132.26/`, `http://200.165.238.242/` продолжают отдавать `200`.
На каждой машине: ровно один процесс `frps.exe`, порты `7000` и `9966` слушают
как раньше, службы CMSV6 (`gpstomcat6`, `GPSLoginSvr`, `GPSMediaSvr`,
`GPSMysqld` и остальные `GPS*`) — в том же состоянии, что до правки, и ни одна
не перезапускалась. Отдельно снять `Get-NetTCPConnection -State Listen` по
портам `443`, `16604`, `16605` ещё раз через несколько минут после снятия
nginx и записать, появился ли на них новый слушатель и какой процесс им владеет
— это единственное измеримое проявление «конфликта с программой» из текста
задачи. Найденное записать как факт в CLAUDE.md и в чат задачи; ничего по
этому поводу не чинить и не настраивать — это вне объёма задачи.

**5. Документация — основной артефакт этого репозитория.** В `CLAUDE.md`:

- в таблицу `### Scheduled tasks (autostart)` сервера 1 и в раздел
  `### Автозапуск` сервера 2 внести, что задача `nginx_run` переведена в
  `Disabled` 07.09.2026 задачей IPRSV1-19, с причиной из текста задачи
  (конфликт с программой, механизм не назван) и с прямой цитатой ответа
  Максима «давай руби на обе»;
- в разделе `## Web entry points (80 / 443)` сервера 1 и в разделе
  `### nginx` сервера 2 привести в соответствие все утверждения о работающем
  HTTPS: строка таблицы `https://scanvision.online/` → `200` и фраза «HTTPS
  from outside now works», описание листенеров `443`/`16604`/`16605` — сейчас
  они не отвечают, потому что nginx выключен вручную, а не потому что что-то
  сломалось;
- в `### Certificates` сервера 1 и в `### win-acme и сертификат` сервера 2
  добавить, что сертификаты остались на месте и продолжают продлеваться, но
  никем не отдаются, пока nginx выключен. Про сервер 2 указать факт: у
  продления `scan-vision.ru` установочный шаг — скрипт
  `C:\nginx\reload-nginx.bat`, который при выключенном nginx ничего не поднимет
  (валидация от этого не страдает — она файловая, webroot `C:\Program
  Files\CMSServerV6\tomcat\webapps\gpsweb`, отдаёт tomcat на порту 80). Про
  сервер 1 указать факт: у продления `test.thedevs.ru` валидация — файловый
  webroot `C:\nginx\html`, хранилище — `C:\nginx\conf\le`; обе величины это
  просто пути на диске, отключение nginx их не меняет;
- завести в обоих разделах явную **процедуру обратного включения** (это прямое
  требование задачи — «чтобы можно было включить обратно при необходимости»):
  `Enable-ScheduledTask -TaskName nginx_run`, затем
  `schtasks /run /tn nginx_run`, затем проверка `Get-Process nginx` +
  `Get-NetTCPConnection -State Listen` на `443`/`16604`/`16605` и внешняя
  проверка `https://` на соответствующем домене; напомнить там же про ловушку
  залипшего мастера и про то, что `-s reload` от `Administrator` не работает;
- записать результат шага 4 (занял ли кто-то `443`/`16604`/`16605` после
  освобождения) как измеренный факт;
- ни одного пароля, токена frps или пароля дашборда в репозиторий не писать
  (правило `## Secrets` в `CLAUDE.md`).

  `Get-ScheduledTask -TaskName nginx_run` → `State Disabled`, задача при этом

- `Get-Process nginx` на обеих машинах не возвращает ни одного процесса, и

  бэкапы конфигов, `conf\le`, `conf\scanvision` (сервер 1),

- frps на обеих машинах жив: ровно один процесс `frps.exe`, порты `7000` и

- Зафиксировано измерением, появился ли новый слушатель на

- `CLAUDE.md` описывает новое состояние обеих машин, причину отключения с

# Не трогать

- **Не удалять nginx** — ни каталог `C:\nginx`, ни `nginx.exe`, ни конфиги и их
  бэкапы, ни сертификаты в `conf\le` и `conf\scanvision`. Задача прямо
  требует обратимости.
- Не удалять и не пересоздавать задачу планировщика `nginx_run` — только
  `Disable-ScheduledTask`.
- Не править `nginx.conf` ни на одной машине (не комментировать `server`-блоки,
  не менять порты) — механизм этой задачи именно выключенный nginx, а не
  переписанный конфиг.
- Не трогать задачи `win-acme renew (acme-v02.api.letsencrypt.org)` на обеих
  машинах, не запускать `wacs.exe --renew --force` (на сервере 2 недельный
  лимит Let's Encrypt по этому набору имён уже расходовался 03.09.2026), не
  менять `C:\nginx\reload-nginx.bat`.
- Не трогать frps: ни `frps.ini`, ни задачи `frps`/`frps-watchdog`, ни токен,
  ни пароль дашборда.
- Не трогать CMSV6: ни службы `GPS*`/`gpstomcat6`, ни `server.xml`, ни базу
  `1010GPS`, ни файлы платформы. Порт `80` остаётся за tomcat, переносить точку
  входа не нужно.
- Не удалять и не менять правила файрвола, включая `nginx 443`, `nginx 80`,
  `GPSNginx`, `iprsv1-13-*`, `iprsv1-17-*`, `iprsv1-18-*`: закрывать порты в
  этой задаче не просили, а их удаление усложнило бы обратное включение.
- Не перезагружать машины, не перезапускать службы CMSV6 и не «чинить» то, что
  займёт освободившиеся порты.
- Не заводить новых зависимостей, секретов репозитория и переменных окружения;
  версии `nginx`/`frps`/CMSV6/win-acme не менять.
