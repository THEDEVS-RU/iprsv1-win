# Контекст

Продолжение задачи IPRSV1-5. Основная спека
`specs/2026-07-30-iprsv1-win-frps-server.md` уже выполнена и слита в `dev`:
frps работает на сервере под задачей планировщика `frps` (SYSTEM, запуск при
старте системы, рабочая папка `C:\Users\Administrator\Desktop\6e9`), снаружи
открыты 7000, 9966, 9967, дашборд намеренно слушает только `127.0.0.1:7500` и в
файрвол не выведен, доступ к нему — через SSH-туннель.

Максим (чат задачи, 2026-07-30): «можем временно открыть дашборд 7500 наружу?
для тестов?» — да, можем; эта спека это и делает.

Состояние на сервере, проверенное замерами 2026-07-30 перед составлением спеки:

- процесс `frps.exe` (PID менялся, старт 30.07.2026 16:04) поднят задачей
  планировщика `frps`, задача в состоянии Running, принципал `SYSTEM`,
  RunLevel Highest, действие `frps.exe -c frps.ini`, рабочая папка — папка
  `6e9`;
- слушатели: `7000`, `9966`, `9967` на всех интерфейсах, `7500` — только на
  `127.0.0.1`;
- снаружи (проверка с раннера): 7000, 9966, 9967 открыты, 7500 недоступен;
- `frps.ini` содержит `bind_port = 7000`, `vhost_http_port = 9966`,
  `vhost_https_port = 9967`, `dashboard_addr = 127.0.0.1`,
  `dashboard_port = 7500`, `dashboard_user = admin`, `tcp_mux = true`, плюс
  сгенерированные `token` и `dashboard_pwd` и настройки лога; рядом лежит
  `frps.ini.vendor-backup`;
- правила файрвола `frps-7000-tcp` и `frps-9966-9967-tcp` заведены, правила на
  7500 нет.

Отсюда объём работы: одного правила файрвола НЕ достаточно — пока
`dashboard_addr = 127.0.0.1`, дашборд физически не слушает внешний интерфейс,
поэтому нужно и поменять адрес, и перезапустить задачу, и открыть порт.

Важное свойство, которое надо знать и записать в документацию: дашборд frps
0.17.0 работает по обычному HTTP без TLS, авторизация — basic auth. Открытый
наружу дашборд означает, что пара `admin`/пароль ходит по сети в открытом виде.
Поэтому доступ открывается как временный, помечен именем правила и должен
закрываться после тестов; постоянный способ доступа остаётся прежним —
SSH-туннель.

# Что сделать

Вся работа — на сервере по SSH (порт 2299, реквизиты из `SERVER`/`LOGIN`/
`PASSWORD`), плюс правка документации в репозитории.

**1. Конфиг.** Modify: `C:\Users\Administrator\Desktop\6e9\frps.ini` на сервере —
одна строка: `dashboard_addr = 0.0.0.0` вместо `127.0.0.1`. Остальные ключи не
трогать: `bind_port`, `vhost_http_port`, `vhost_https_port`, `dashboard_port`,
`dashboard_user`, `dashboard_pwd`, `token`, `tcp_mux`, `log_file`, `log_level`,
`log_max_days` остаются как есть. `subdomain_host` по-прежнему не задаём.

**2. Перезапуск.** Перезапустить задачу планировщика `frps`
(`Stop-ScheduledTask` → `Start-ScheduledTask`), дождаться появления процесса и
проверить по `frps.log`, что старт прошёл (свежие строки
`frps tcp listen on 0.0.0.0:7000` и `Start frps success` с текущей датой).
Задачу не пересоздавать и её параметры (триггер, принципал, рабочую папку) не
менять. Лишних экземпляров `frps.exe` в процессах остаться не должно.

**3. Правило файрвола.** Создать входящее разрешающее правило на TCP 7500 с
именем `frps-7500-tcp-temp` — имя с суффиксом `temp` маркирует, что правило
временное и подлежит удалению после тестов. Правило по порту (не по программе),
как уже существующие `frps-7000-tcp` и `CMSv6-*`. Существующие правила не
менять.

**4. Проверка снаружи.** С раннера (не с самой машины) убедиться, что
`http://<адрес из SERVER>:7500` отвечает: без реквизитов — 401, с
`admin` и паролем из `dashboard_pwd` (взять из `frps.ini` на сервере, в вывод
не печатать) — 200 и страница дашборда. Порты 7000/9966/9967 должны остаться
открытыми, дашборд-порт 7500 — открытым только этим правилом.

**5. Документация.** Modify: `CLAUDE.md` в корне репозитория — раздел про
дашборд сейчас утверждает, что он слушает только `127.0.0.1:7500` и «never
opened in the firewall»; после этой задачи это неправда. Привести раздел в
соответствие: дашборд слушает `0.0.0.0:7500`, наружу открыт временным правилом
`frps-7500-tcp-temp` для тестов, обычный способ доступа остаётся через
SSH-туннель, соединение идёт по HTTP без шифрования (basic auth уходит в сеть
открытым текстом — пароль дашборда нигде больше не переиспользовать). Там же —
как вернуть закрытое состояние: удалить правило `frps-7500-tcp-temp`, вернуть
`dashboard_addr = 127.0.0.1` в `frps.ini`, перезапустить задачу `frps`. Значения
`token`, `dashboard_pwd` и реквизитов сервера в файл по-прежнему не писать.
