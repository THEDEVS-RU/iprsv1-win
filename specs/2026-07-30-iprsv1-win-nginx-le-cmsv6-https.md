# Контекст

Задача IPRSV1-8: домен `scanvision.online` уже делегирован на сервер проекта, и
веб-интерфейс CMSV6 должен открываться прямо по этому имени — без ввода порта и
IP, по HTTPS с сертификатом Let's Encrypt, который выпускается и продлевается
автоматически.

Замеры на сервере и снаружи, сделанные 30.07.2026 перед составлением спеки
(read-only, ничего не менялось):

- `scanvision.online` и `www.scanvision.online` резолвятся в адрес из секрета
  `SERVER` — обе A-записи уже настроены. Wildcard-записи нет
  (`test.scanvision.online` не резолвится) — для этой задачи она и не нужна.
- На сервере на портах 80 и 443 не слушает никто, правил файрвола на эти порты
  нет; профили файрвола (Domain/Private/Public) включены, `DefaultInboundAction`
  = `NotConfigured`, то есть входящие по умолчанию блокируются.
- Снаружи (проверка с раннера): 7000, 7500, 8080, 9966, 9967, 6608, 2299 —
  открыты; 80 и 443 — таймаут. Таймаут объясняется отсутствием слушателя и
  правила файрвола, поэтому по нему **нельзя** судить о состоянии security group
  Aliyun ни для 80, ни для 443.
- Список открытых портов SG в описании задачи неполон: 8080, 6608 и 2299
  доступны снаружи, хотя в списке не значатся. Поэтому про 443 нельзя заранее
  утверждать ни что он открыт, ни что закрыт — это выясняется только опытом,
  после того как на порту появится слушатель и правило Windows-файрвола.
- Веб CMSV6 — служба `gpstomcat6` на порту 8080 (HTTP, без TLS: в
  `C:\Program Files\CMSServerV6\7.37.2_20260710\tomcat\conf\server.xml` один
  Connector с `port="8080"` и `redirectPort="8443"`, SSL-коннектора нет).
  Снаружи 8080 открыт правилом `CMSv6-2121-2122-6617-2162-8080-tcp`. Корень
  отдаёт редирект на `808gps/login.html`, версия веба 7.37.2_20260710.
- Реверс-прокси и ACME-клиента на машине нет: служб `nginx`/`caddy` нет, роль
  IIS `Web-Server` в состоянии `Available` (не установлена).
- Исходящие соединения с сервера работают: TCP 443 до
  `acme-v02.api.letsencrypt.org`, `github.com` и `objects.githubusercontent.com`
  проходят, WinHTTP-прокси не настроен («Direct access»). В системе есть
  `curl.exe`, `tar.exe`, `certutil.exe`, PowerShell 5.1, на диске C: свободно
  221 ГБ.
- frps занимает 7000 (bind), 9966/9967 (vhost http/https) и 7500 (дашборд) —
  с 80 и 443 не пересекается, трогать его не нужно.

Решение Максима в чате задачи (30.07.2026): ставим **nginx + win-acme**, и веб
CMSV6 должен открываться и по 80, и по 443 — принудительного редиректа с HTTP на
HTTPS не делаем.

Риск, который надо знать заранее и проверить при реализации (это именно риск, а
не установленный факт — под HTTPS без учётной записи в CMSV6 его проверить
нельзя): часть фронтенда CMSV6 строит адреса не относительно текущей страницы.
В `webapps\gpsweb\js\index.js` (строка 123) websocket-адрес собирается как
`"ws://" + window.location.host + "/upgradeSocket"` — жёстко незащищённая схема,
которую браузер на HTTPS-странице заблокирует; а адреса видеопотоков плеер
получает от сервера полями `psl`/`dsl` (`webapps\gpsweb\808gps\js\activeSafetyScreen.js`),
и что именно там придёт — абсолютный адрес с портом медиасервера или
относительный — из статики не видно. Основной вебсокет самого интерфейса
(`webapps\gpsweb\js\webSocket.js`) собирается от `window.location`, то есть через
прокси пойдёт нормально при правильных заголовках Upgrade. Именно поэтому вход
по 80 сохраняется рабочим, а 8080 не закрывается — это запасные пути, если под
HTTPS отвалится живое видео.

IPRSV1-7 (прописать `subdomain_host` в frps и связать с CMSV6) — отдельная
задача, эту она не блокирует и пересечений по портам с ней нет.

# Что сделать

Вся работа — на сервере по SSH (порт 2299, реквизиты из `SERVER`/`LOGIN`/
`PASSWORD`), многострочный PowerShell подавать только через `-EncodedCommand`
(см. `CLAUDE.md` в корне репозитория), плюс правка документации в репозитории.
Порядок шагов важен: nginx поднимается сначала только на 80, потому что nginx не
стартует с `ssl_certificate`, указывающим на несуществующий файл, а сертификата
до валидации ещё нет.

**1. Установка nginx.** Create: `C:\nginx` — распаковать туда актуальную stable
Windows-сборку с nginx.org (на дату спеки stable — ветка 1.28.x, архив
`https://nginx.org/download/nginx-1.28.0.zip`; если этой версии на зеркале уже
нет, взять текущую stable-версию со страницы `https://nginx.org/en/download.html`).
Скачивать `curl.exe`, распаковывать `Expand-Archive`; в итоге `C:\nginx\nginx.exe`,
`C:\nginx\conf\`, `C:\nginx\html\`, `C:\nginx\logs\`. Проверить `nginx.exe -v` и
записать поставленную версию. Новых пакетных менеджеров не ставить.

**2. Конфиг nginx, первый этап (только 80).** Modify:
`C:\nginx\conf\nginx.conf` — заменить вендорский `server`-блок на конфигурацию
проекта. Пути в конфиге писать через прямые слэши. Обязательные элементы:

```nginx
http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile        on;
    keepalive_timeout  65;
    client_max_body_size 1024m;

    map $http_upgrade $connection_upgrade {
        default upgrade;
        ''      close;
    }

    server {
        listen 80;
        server_name scanvision.online www.scanvision.online;

        location /.well-known/acme-challenge/ {
            root C:/nginx/html;
        }

        location / {
            proxy_pass http://127.0.0.1:8080;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection $connection_upgrade;
            proxy_buffering off;
            proxy_read_timeout 3600s;
            proxy_send_timeout 3600s;
        }
    }
}
```

Заголовок `Strict-Transport-Security` (HSTS) не добавлять — он запретил бы
браузеру ходить на этот домен по HTTP, а вход по 80 у нас остаётся штатным.
Проверить конфиг `nginx.exe -t`.

**3. Правила файрвола.** Создать входящие разрешающие правила по портам (не по
программе), в том же стиле, что существующие `frps-7000-tcp` и `CMSv6-*`:
`nginx-80-tcp` (TCP 80) и `nginx-443-tcp` (TCP 443). Существующие правила не
менять.

**4. Автозапуск.** Оформить задачу планировщика `nginx` по образцу уже
работающей задачи `frps`: триггер «при старте системы», принципал `SYSTEM`,
RunLevel Highest, рабочая папка `C:\nginx`, действие `C:\nginx\nginx.exe`,
перезапуск при сбое 3 раза с интервалом 1 минута. Запустить задачу и убедиться,
что процессы `nginx.exe` (мастер + воркер) живут, а порт 80 слушается. Процесс,
запущенный интерактивно по SSH, умрёт вместе с сессией — поэтому только задача
планировщика.

**5. Проверка HTTP снаружи.** С раннера (не с самой машины) убедиться, что
`http://scanvision.online/` и `http://www.scanvision.online/` отдают страницу
входа CMSV6 (редирект на `808gps/login.html`, дальше 200). Если 80 снаружи
недоступен при поднятом слушателе и заведённом правиле файрвола — это закрытый
порт в security group Aliyun: остановиться, вызвать
`update_task(taskCode="IPRSV1-8", awaitingReply=true)` и одной строкой попросить
Максима открыть входящий TCP 80 в консоли Aliyun. Без работающего 80 валидация
Let's Encrypt по http-01 не пройдёт.

**6. Установка win-acme.** Create: `C:\win-acme` — распаковать туда актуальный
релиз `win-acme.v2.*.x64.pluggable.zip` со страницы релизов
`https://github.com/win-acme/win-acme/releases` (архив pluggable, не trimmed —
в нём есть плагины хранилища и установки). Create: `C:\nginx\reload-nginx.bat` —
батник из двух строк: переход в `C:\nginx` (`cd /d C:\nginx`) и `nginx.exe -s reload`.

**7. Выпуск сертификата.** Запустить win-acme в unattended-режиме:

```
C:\win-acme\wacs.exe --source manual --host scanvision.online,www.scanvision.online ^
  --friendlyname scanvision.online ^
  --validation filesystem --webroot C:\nginx\html ^
  --store pemfiles --pemfilespath C:\nginx\ssl ^
  --installation script --script C:\nginx\reload-nginx.bat ^
  --accepttos --emailaddress admin@scanvision.online
```

Контактный адрес ACME-аккаунта — `admin@scanvision.online`: Let's Encrypt шлёт
на него только письма об истечении сертификата и доставку не проверяет; если
Максим в чате задачи назовёт другой адрес, использовать названный. В сборках
win-acme старше 2.2 параметр `--source` называется `--target` — если бинарь не
принимает `--source`, передать `--target` с тем же значением. После выпуска
посмотреть, какие файлы реально появились в `C:\nginx\ssl` (хранилище pemfiles
кладёт файлы, названные по friendly name, — цепочка и ключ отдельными файлами),
и использовать в конфиге именно эти имена, а не предполагаемые.

**8. Конфиг nginx, второй этап (443).** Modify: `C:\nginx\conf\nginx.conf` —
добавить второй `server`-блок: `listen 443 ssl;`, тот же `server_name`,
`ssl_certificate` — файл цепочки из `C:/nginx/ssl`, `ssl_certificate_key` — файл
ключа оттуда же, `ssl_protocols TLSv1.2 TLSv1.3;`, `ssl_session_cache shared:SSL:10m;`,
и тот же `location /` с проксированием на `http://127.0.0.1:8080` и теми же
заголовками (Host, X-Real-IP, X-Forwarded-For, X-Forwarded-Proto, Upgrade,
Connection), `proxy_buffering off`, теми же таймаутами. Блок на 80 оставить как
есть — он продолжает и отдавать сайт, и обслуживать ACME-проверки. `nginx.exe -t`,
затем `nginx.exe -s reload`.

**9. Проверка HTTPS снаружи.** С раннера: `https://scanvision.online/` и
`https://www.scanvision.online/` отдают страницу входа CMSV6, сертификат выдан
Let's Encrypt, покрывает оба имени, цепочка полная (проверять без `-k`, чтобы
поймать неполную цепочку). Порт 8080 продолжает отвечать по HTTP. Если 443
снаружи недоступен при поднятом слушателе и заведённом правиле файрвола — это
закрытый порт в security group Aliyun: остановиться, вызвать
`update_task(taskCode="IPRSV1-8", awaitingReply=true)` и попросить Максима
открыть входящий TCP 443 в консоли Aliyun.

**10. Проверка автопродления.** Убедиться, что win-acme создал свою задачу
планировщика (её имя вида `win-acme renew (acme-v02.api.letsencrypt.org)`), она
включена и запускается от `SYSTEM`. Затем один раз прогнать принудительное
продление `C:\win-acme\wacs.exe --renew --force` и убедиться по результату, что
цикл рабочий целиком: в `C:\nginx\ssl` файлы обновились (свежие даты
изменения), в выводе win-acme нет ошибок, скрипт установки отработал, а
`C:\nginx\logs\error.log` не содержит ошибок перезагрузки; HTTPS снаружи
продолжает отвечать новым сертификатом. Больше одного принудительного продления
не делать — у Let's Encrypt есть недельный лимит на повторный выпуск того же
набора имён.

**11. Проверка живого интерфейса.** Открыть CMSV6 через `http://scanvision.online`
и `https://scanvision.online` и сравнить поведение: страница входа, вход в
систему, основной websocket интерфейса (в `nginx\logs\access.log` запросы к
`/ws/webSocket/...` должны отдавать 101, а не 400/502). Отдельно проверить живое
видео под HTTPS — если оно не работает из-за смешанного содержимого (плеер или
`/upgradeSocket` тянут `ws://`/`http://`), это не повод откатывать задачу:
зафиксировать факт в `CLAUDE.md` как известное ограничение и в итоге стадии, а
рабочими путями остаются `http://scanvision.online` и прямой `:8080`.

**12. Проверка, что CMSV6 не пострадала.** Службы `GPSDaemon`, `GPSGatewaySvr`,
`GPSMediaSvr`, `GPSLoginSvr`, `GPSUserSvr`, `GPSDownSvr`, `GPSStorageSvr`,
`GPSDataProcSvr`, `GPSGeocodeSvr`, `GPSFtpd`, `gpstomcat6`, `GPSMysqld` — в
состоянии Running; `http://<адрес из SERVER>:8080/` отвечает 200; порты
6601–6635 и 6608 снаружи по-прежнему открыты; frps (7000/9966/9967/7500) работает
как работал.

**13. Документация.** Modify: `CLAUDE.md` в корне репозитория — добавить раздел
про веб-вход по домену: что стоит (`C:\nginx`, `C:\win-acme`, поставленные
версии), какие порты заняты (80 и 443 — nginx, 8080 — прямой вход в CMSV6,
остаётся открытым), задача планировщика `nginx` и задача продления от win-acme,
где лежат сертификат и ключ (`C:\nginx\ssl`), как перечитать конфиг
(`nginx.exe -s reload`) и как выглядит ручное продление, почему нет HSTS и нет
редиректа с 80 на 443, а также найденное ограничение по живому видео под HTTPS,
если оно подтвердится на шаге 11. В разделе про состав машины упомянуть nginx
рядом с CMSV6 и frps. Значения секретов, `token` и пароля дашборда frps в файл
по-прежнему не писать.

# Критерии готовности

- `http://scanvision.online/` и `http://www.scanvision.online/` снаружи отдают
  страницу входа CMSV6.
- `https://scanvision.online/` и `https://www.scanvision.online/` снаружи отдают
  ту же страницу с валидным сертификатом Let's Encrypt на оба имени, полной
  цепочкой и без предупреждений браузера (проверка `curl` без `-k` проходит).
- Ни один адрес не требует указывать порт или IP вручную.
- В `C:\nginx\conf\nginx.conf` есть оба server-блока (80 и 443), конфиг проходит
  `nginx.exe -t`, заголовка HSTS нет, редиректа с 80 на 443 нет.
- Задача планировщика `nginx` в состоянии Running, автозапуск при старте
  системы; процессы `nginx.exe` живы после закрытия SSH-сессии.
- Правила файрвола `nginx-80-tcp` и `nginx-443-tcp` заведены и включены;
  существующие правила не изменены.
- Задача продления от win-acme существует, включена, запускается от `SYSTEM`;
  принудительный прогон `--renew --force` выполнен один раз и завершился
  обновлением файлов в `C:\nginx\ssl` и успешной перезагрузкой nginx без ошибок
  в `C:\nginx\logs\error.log`.
- Поведение CMSV6 через прокси проверено: вход в систему работает, запросы
  `/ws/webSocket/...` в `access.log` отдают 101; состояние живого видео под
  HTTPS проверено и зафиксировано в `CLAUDE.md` (работает — так и написано; не
  работает из-за смешанного содержимого — записано как известное ограничение с
  рабочими обходными путями).
- CMSV6 не затронута: все её службы Running, прямой вход `http://<адрес из
  SERVER>:8080/` отвечает 200, порты 6601–6635 и 6608 снаружи открыты, frps
  работает на 7000/9966/9967/7500.
- `CLAUDE.md` в `dev` описывает nginx и win-acme (пути, версии, задачи
  планировщика, файлы сертификата, перезагрузка конфига, ручное продление,
  отсутствие HSTS и редиректа, ограничения) — без значений секретов, `token` и
  пароля дашборда.
- Ни в чате, ни в PR, ни в логах прогонов нет значений `PASSWORD`, `LOGIN`,
  `SERVER`, `token`, `dashboard_pwd` и приватного ключа сертификата.

# Не трогать

- CMSV6: службы `GPS*`, `gpstomcat6`, `GPSMysqld`, файлы в
  `C:\Program Files\CMSServerV6` (включая `tomcat\conf\server.xml` — TLS в самом
  Tomcat не включаем), порты 2121/2122/2162/6601–6635/8080 и правила `CMSv6-*`.
  Порт 8080 остаётся открытым снаружи — это запасной вход, закрывать его не
  надо.
- frps: `frps.ini`, задача планировщика `frps`, порты 7000/9966/9967/7500 и
  правила `frps-*`. `subdomain_host` не задавать — это работа задачи IPRSV1-7.
- Правила `OpenSSH 2299`, `Zabbix` не менять; файрвол и Windows Defender целиком
  не отключать; сервер не перезагружать; чужие службы не перезапускать
  (перезапускается только nginx и только своими средствами).
- DNS-записи домена не менять, новые поддомены не заводить.
- Принудительное продление сертификата больше одного раза не запускать —
  недельный лимит Let's Encrypt на повторный выпуск одного и того же набора
  имён.
- Приватный ключ и содержимое `C:\nginx\ssl` в репозиторий, PR, чат и логи не
  переносить.
- В `CLAUDE.md` править только раздел про состав машины (упоминание nginx) и
  добавлять новый раздел про веб-вход по домену; разделы про SSH-подключение,
  CMSV6 и frps оставить как есть. `README.md` и спеки в `specs/` не трогать.
- Ветку `master`/`main` не создавать — работа от `dev`.
