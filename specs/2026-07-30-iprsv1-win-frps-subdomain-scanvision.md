# Контекст

Задача IPRSV1-7: домен `scanvision.online` подключён, надо привязать к нему frps
и связать его с CMSV6. Инструкция вендора (файл «frps server .docx») описывает
три шага: поменять `subdomain_host` в `C:\frps\frps.ini`, перезапустить frps
командой `frps.exe -c frps.ini` из его папки и прописать
`D:\Program Files (x86)\CMSV6\plugin\config\libconfig_27\frpcSet.xml`.

Факты, снятые прямыми замерами на сервере и во внешнем DNS 2026-07-30. Пути в
инструкции — со стенда вендора, у нас раскладка другая, поэтому шаги ниже
переписаны под реальную машину:

- frps лежит не в `C:\frps`, а в `C:\Users\Administrator\Desktop\6e9`:
  `frps.exe` (fatedier/frp 0.17.0), `frps.ini`, `frps.ini.vendor-backup`,
  `frps.log`.
- Текущая секция `[common]` в `frps.ini`: `bind_port = 7000`,
  `vhost_http_port = 9966`, `vhost_https_port = 9967`,
  `dashboard_addr = 0.0.0.0`, `dashboard_port = 7500`, `dashboard_user = admin`,
  `dashboard_pwd` (сгенерированный), `token` (сгенерированный),
  `tcp_mux = true`, `log_file`, `log_level = info`, `log_max_days = 7`. Ключа
  `subdomain_host` в файле НЕТ вообще — его надо добавить, а не заменить:
  `fleetcamai.com` со скриншота инструкции — значение вендорского стенда, у нас
  такой строки никогда не было.
- frps работает не консолью, а задачей планировщика Windows `frps`: состояние
  Running, принципал SYSTEM, действие `frps.exe` с аргументом `-c frps.ini`,
  рабочая папка `C:\Users\Administrator\Desktop\6e9`, триггер «при старте
  системы». Поэтому шаг 2 инструкции (`cd C:\frps\` и запуск `frps.exe`) у нас
  выполнять нельзя: поднимется второй экземпляр, который будет драться за порт
  7000 с уже работающим, и умрёт при закрытии SSH-сессии (OpenSSH убивает
  процесс вместе с сессией). Смысл вендорского «запускать из его директории» —
  рабочая папка для относительных путей `-c frps.ini` и лога; у задачи
  планировщика она уже задана правильно, ошибки authorization failed / broken
  pipe из инструкции этим и лечатся.
- CMSV6 на сервере — серверная часть `C:\Program Files\CMSServerV6` (версия
  `7.37.2_20260710`, службы `GPS*`, `gpstomcat6` на 8080, `GPSMysqld` на
  127.0.0.1:3311). Диска `D:` на машине нет вообще, каталога `CMSV6` в
  `Program Files (x86)` нет, каталогов `libconfig_*` и файла `frpcSet.xml` нет
  нигде на диске (искал рекурсивно по `C:\Program Files`,
  `C:\Program Files (x86)`, `C:\Users`, `C:\ProgramData` и по всему дереву
  CMSV6), в веб-приложении `gpsweb` строка `frpc` не встречается ни в одном
  `.js`/`.html`. Путь из инструкции — это установка КЛИЕНТА CMSV6: инсталлятор
  `CMSV6_WIN_7.37.2_20260710.exe` платформа раздаёт по
  `/product/cmsv6/install/`, ставится он в `Program Files (x86)\CMSV6` на машину
  оператора. `libconfig_27` — библиотека параметров устройств FactoryType 27
  (тип регистраторов заказчика). То есть третий шаг инструкции выполняется не на
  нашем сервере.
- DNS: `scanvision.online` и `www.scanvision.online` резолвятся в адрес сервера
  (значение переменной `SERVER`), NS зоны — `ns1.reg.ru` и `ns2.reg.ru`.
  Wildcard-записи нет: произвольное имя третьего уровня отдаёт NXDOMAIN. Для
  механизма `subdomain` это критично — frps отдаёт клиенту хост вида
  `<имя>.scanvision.online`, и без wildcard-записи такой хост не резолвится ни у
  кого. Реквизитов reg.ru в репозитории нет (есть только `SERVER`, `LOGIN`,
  `PASSWORD`), значит запись заводит человек: эта задача её не создаёт, а
  проверяет и сообщает.

# Что сделать

Работа на сервере по SSH (порт 2299, реквизиты `SERVER`/`LOGIN`/`PASSWORD`;
многострочный PowerShell — только через `-EncodedCommand`, см. `CLAUDE.md`),
плюс правка документации в репозитории. Ничего не устанавливать, машину не
перезагружать, новых портов в файрвол не открывать — `subdomain` работает поверх
уже открытых 9966/9967.

**1. Домен в конфиге frps.** Modify: `C:\Users\Administrator\Desktop\6e9\frps.ini`
на сервере (файл на машине, не в репозитории) — добавить в секцию `[common]`
ровно одну строку:

```
subdomain_host = scanvision.online
```

Перед правкой снять копию рядом с именем `frps.ini.bak-2026-07-30` (откат одной
командой); вендорский `frps.ini.vendor-backup` не трогать и не перезаписывать.
Значение — зона без `www`: `subdomain_host` задаёт родительский домен, к
которому frps приклеивает `subdomain` клиента. Остальные ключи не менять ни
одним символом: `bind_port`, `vhost_http_port`, `vhost_https_port`,
`dashboard_addr`, `dashboard_port`, `dashboard_user`, `dashboard_pwd`, `token`,
`tcp_mux`, `log_file`, `log_level`, `log_max_days`. Формат файла остаётся INI —
сборка 0.17.0 не понимает TOML/YAML.

**2. Перезапуск — задачей планировщика, не консолью.** `Stop-ScheduledTask
-TaskName 'frps'`, дождаться исчезновения процесса `frps.exe`, затем
`Start-ScheduledTask -TaskName 'frps'`. Параметры задачи (триггер, принципал,
рабочую папку, RunLevel) не менять, задачу не пересоздавать, `frps.exe -c
frps.ini` руками в SSH-сессии не запускать. После старта в
`C:\Users\Administrator\Desktop\6e9\frps.log` должны появиться свежие строки с
текущей датой — те самые, что вендорская инструкция ждёт в консоли:

- `frps tcp listen on 0.0.0.0:7000`
- `http service listen on 0.0.0.0:9966`
- `https service listen on 0.0.0.0:9967`
- `Dashboard listen on 0.0.0.0:7500`
- `Start frps success`

Процесс `frps.exe` в системе должен остаться ровно один.

**3. Проверка снаружи, с раннера (не с самой машины).** Порты 7000, 9966, 9967
по-прежнему открыты. Плюс проверка, что http-vhost реально обслуживает домен:
запрос на порт 9966 по адресу из `SERVER` с заголовком
`Host: probe.scanvision.online` должен вернуть HTTP-ответ самого frps (404 «not
found» — клиента с таким subdomain нет), а не ошибку соединения; ошибка
соединения означает, что vhost не поднялся, и тогда надо разбираться с логом, а
не идти дальше.

**4. DNS — проверить и сообщить, ничего не менять.** С раннера проверить, что
`scanvision.online` и `www.scanvision.online` резолвятся в адрес из `SERVER`, и
отдельно — резолвится ли произвольное имя третьего уровня в этой зоне (на
2026-07-30 не резолвилось). Если wildcard по-прежнему отсутствует, написать об
этом в отчёте стадии открытым текстом: для работы `subdomain`-прокси в зоне
`scanvision.online` (reg.ru) нужна A-запись с именем `*` на адрес сервера, без
неё имена вида `<имя>.scanvision.online` не откроются ни у кого, хотя frps
настроен верно. DNS-записи этой задачей не создаются и не правятся — реквизитов
регистратора у нас нет.

**5. Связка с CMSV6 — подготовить блок, путь на сервере не выдумывать.** Файл
`frpcSet.xml` принадлежит клиенту CMSV6 на машине оператора
(`…\Program Files (x86)\CMSV6\plugin\config\libconfig_27\frpcSet.xml`); на нашем
сервере ни этого каталога, ни клиента нет. Клиент CMSV6 не устанавливать, файл
«по аналогии» где-то на сервере не создавать. Вместо этого вынести в отчёт
стадии готовый к применению блок — дословно как в задаче, с единственной
подстановкой (токен):

```xml
<FRPC version="1.0.0">
  <ServerIp>www.scanvision.online</ServerIp>
  <ServerPort>7000</ServerPort>
  <TokenForCon>{значение token из frps.ini}</TokenForCon>
  <ViewPort>9966</ViewPort>
  <isOpenFunc>1</isOpenFunc>
</FRPC>
```

Значение `token` читается по SSH из `frps.ini` на сервере и передаётся тому, кто
настраивает клиент; в репозиторий, PR, коммиты, чат и логи прогонов оно не
попадает. В отчёте стадии задать Максиму вопрос: на какой машине установлен
клиент CMSV6, куда класть этот файл.

**6. Документация.** Modify: `CLAUDE.md` в корне репозитория, раздел `## frps`:

- абзац «`subdomain_host` is intentionally not set …» после этой задачи неверен —
  заменить на актуальное: `subdomain_host = scanvision.online`, зона на
  NS reg.ru, apex и `www` смотрят на адрес сервера, wildcard-запись `*` —
  обязательное условие для subdomain-прокси, с её фактическим статусом по итогам
  п.4;
- добавить пункт про CMSV6: связка делается файлом `frpcSet.xml` в каталоге
  клиента CMSV6 (`…\Program Files (x86)\CMSV6\plugin\config\libconfig_27\`) на
  машине оператора, поля `ServerIp` = `www.scanvision.online`, `ServerPort` =
  7000, `TokenForCon` = `token` из `frps.ini` (читается по SSH), `ViewPort` =
  9966 (это `vhost_http_port` frps), `isOpenFunc` = 1; на сервере такого
  каталога нет — серверная часть CMSV6 стоит в `C:\Program Files\CMSServerV6`;
- зафиксировать, что перезапуск frps делается только через задачу планировщика
  `frps`, а запуск `frps.exe` из SSH-сессии создаёт конкурирующий экземпляр.

Значения `token`, `dashboard_pwd`, `LOGIN`, `PASSWORD`, `SERVER` в файл не
писать — правило раздела `## Secrets` в `CLAUDE.md`.
